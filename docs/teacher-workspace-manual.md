# 教师端使用与人工验收

## 如何开始

演示模式启动时，若不存在同名账号，系统创建 `teacher / Teach2026!`。账号在同一登录页使用，教师登录后直接进入教师工作台。正式教师由创业者登录，在「创建学生或教师账号」选择教师后建立；公开注册仍然只创建学生。不会将已有同名账号改为教师。

1. 教师点击「新建班级」，只填写名称。班级不绑定项目，学生加入一次即可自由选择多个实训。
2. 复制10位班级码，交给学生。学生登录，在项目库点击「我的班级」，输入码、查看班级信息并勾选同意后加入。
3. 学生自行完成诊断与任务提交。加入后教师可按项目读取已有公开学习记录，不用重新创建作品。
4. 教师在「查看实训项目」选择要查看的项目，刷新「学生进度」，点击「查看与指导」。这个选择只切换老师的数据视图，不限制学生选项目。三个页签是学习与作品证据、安排补练、作品复核与留言。
5. 学生重新打开项目，在「我的针对性练习」查看老师意见，展开并完成「教师安排」的题。通过补练后仍须回原任务修改并重交。

本轮没有自动加入学生，也没有替学生完成任务或调用模型做测试。空班级需学生确认加入后才显示记录。演示学生默认不参与班级共性统计，测试时可明确勾选「包含演示学生」。

教师工作台与学生实训页使用统一的左侧导航、顶部位置提示和右侧内容卡片。左侧可以选择／新建班级，并切换学生进度、班级共性问题、AI工作记录。班级码和班级设置在右侧班级卡中；新班操作指引可以展开或收起。小屏设备将导航放在顶部。

## 六项功能

| 功能 | 入口与结果 |
| --- | --- |
| 建班及邀请 | 新建班级、班级设置、学生我的班级；可关闭新加入、换码、移除或退出，个人进度保留 |
| 发现卡点 | 学生进度／详情：当前阶段、实际核验、诊断不足、未完成补练、补练通过但原任务待重交、人工复核请求 |
| 教学证据 | 学生详情：实际作答、平台协助、首次无提示新实例、最近30条非私人聊天的实训AI记录 |
| 确认补练 | AI／人工草案，修改技能、题型、难度及说明，确认发送或拒绝；系统生成并核验新题 |
| 作品复核 | 留言、服务时间、可选报告0—25／答辩0—15整数分；保留原评价与理由；待复核请求须逐项勾选，评分本身不自动结清其他项目 |
| 班级共性问题 | 程序按技能统计人数，默认排除演示学生；AI提出讲解行动，旧建议在资料改变后标为过期 |

「材料版本」指本次数据或源码提交的版本，用于判断旧草案是否仍适用。「证据编号」对应真实检查或公开学习记录，方便核对安排理由。「无平台提示」只表示站内未使用提示，不能证明没有使用外部AI。

教师只能查看自己班级成员的各实训项目公开学习记录。学生加入预览明确说明共享范围，班级不替学生选择项目。私人答疑聊天、练习答案、密钥、源码存储路径不会发送给教师。软件工程源码查看只读取当前A训练版本，每次最多200行，不展示独立B测评源码。退出或移除后，教师不能继续读取学生；已发送的个人练习保留。

## AI具体怎样工作

### 补练草案

教师点按钮后，服务器检查身份、班级归属、成员关系、明确选择的项目、学习版本和独立测评限制。将当前错误、公开作答、进度与批准题型构建为上下文，使用已有服务端 `AI_API_KEY / AI_BASE_URL / AI_MODEL` 调用 `run_agent('teacher_plan', ...)`。浏览器不接触密钥，不需新增配置。

模型只能调用 `save_teaching_proposal`，提供 `skill_id / template_id / difficulty / reason / teacher_message / evidence_ids`。服务器核对技能、题型、1—3级难度、文字及实际证据后保存草案。未知错因保持待辨别。记录保存模型、工具验证、状态、用量、费用与耗时；此时学生未收到题。

教师检查、修改后点击「确认发送给学生」。服务器再次检查草案所属项目、班级与学习版本，调用 `learning.create_exercise` 和既有模板生成新实例，私有答案由服务器计算，学生只收到公开题干、选项和教师说明。发题、学习状态、说明及草案处理结果一起提交。活跃同技能旧题不会被覆盖；过期草案、重复确认或独立阶段会报错。

模型服务失败或参数非法时保留记录并显示原因，不发题。无模型也能手动建草案走相同确认流程。AI不能直接评分、发题或替学生提交。

### 班级教学建议

程序先计算每个技能存在待练问题的学生数；同一技能每位学生计一次。模型只收到匿名汇总，不收到账号或私人聊天。`run_agent('teacher_class', ...)` 只能调用 `save_class_insights`；每条技能建议必须引用对应技能的实际统计证据。

结果保存在本班当前查看项目的AI工作记录，显示项目和统计范围。记录变化后旧建议标为过期，需要老师主动重新生成。没有自动全班发题或修改成绩。费用按实际用量和已有费率计量，未知费用不按零处理。

### 教学证据的状态区分

教师列表和详情区分未提交、已提交未检查、检查中、超时、环境失败及有效核验。没有有效核验时显示暂无有效成绩，不将它当作零分技能错误。工程只展示当前A版本安全检查摘要，原始执行日志不对教师开放。班级统计显示读取时间，并提示检查尚未完成的人数。

销售分析详情展示学生实际指标和分组表、通过状态与报告引用的证据编号。未通过的数据不能当成正确数据；旧报告会明确提示需更新。

### 处理待复核请求

在「作品复核与留言」阅读每项待复核理由，只勾选本次已经处理的项目。默认不结清任何旧请求，单纯评分或留言不会清空队列。保存前若学生记录变化，会要求重新读取。

| 草案确认 | 修改说明、难度再确认；学生展开补练看到教师安排，客观原分不变 |

| 模型失败 | 服务不可用或额度不足时显示原因、保留记录、不发题 |
| 教师题保留 | 老师发题后学生请求AI安排／提交原任务触发自动教练，已有教师题、来源、理由和作答保留 |
| 复核请求逐项处理 | 仅评报告不清空技能请求；勾选一项后只有该项结清，其余待办保留 |
| 工程核验状态 | 未提交、未检查、运行中、超时、环境失败和有效成绩显示不同说明 |
| 零售报告依据 | 查看指标提交值、品类／渠道／八周分组表及匹配证据编号，区分未通过／已核验／旧报告 |
| 同班并发AI | 仅一项同班AI任务处理，另一项收到等待提示 |
| 小屏／长文 | 班级窗口、长报告和草案可滚动，按钮、焦点及错误提示合理 |
