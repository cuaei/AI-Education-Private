# 版本與接手計劃

整理日期：2026-11-04。這是根據現有文件整理的交接計劃；近期順序是建議，不代表新增產品需求或使用者已確認後續版本。

## 2026-11-05 新方向與近期批次

已確認第一版面向一名學生，Java 後端學習路線、綜合實作和網上商店模擬實習構成目標流程；詳見[需求總覽](項目需求總覽.md)。以下是建議順序，並非已完成的開發或驗收。每批按實際情況交付後停止供使用者驗收；需先確認執行條件和對舊資料的保護。

1. **資源與環境核對**：核對現有網站、推薦資料的章節、免費和內地可訪問性；調查服務器規格、Java 隔離執行與成本，驗收以實測結果為準，不讀取或覆寫現有學生資料。
2. **可操作的學習路線**：在保留舊資料及程式前提下隱藏舊入口，展示 Java 路線、已核實的資源和可保存的進度，提供受每日額度限制的 AI 答疑。驗收重新登入後進度、入口保護及額度行為。
3. **綜合實作**：提供新場景的起始項目，完成本機上傳、安全檢查、評分和三次機會／重設流程；驗收正常、失敗、故障不扣次和 70 分加必要門檻。（2026-11-05：本機初版已實作，見下方「第二批」；待總指揮及使用者驗收。）
4. **商店模擬實習**：學生接手商店，本機操作，依序完成商品查詢、建立及查看訂單；驗收同一項目延續、檢查、AI 按需解釋及次數重設。（2026-11-05：本機初版已實作，見下方「第二批」；待總指揮及使用者驗收。）

以上是按依賴提出的候選批次，不代表每項已確認技術可行，也不承諾工期；若 Java 執行受限須先回報。AI 公司同事／導師屬 V2 或之後的想法，具體版本待定；其他崗位及 V2／V3 細節待定。下方舊 V1 是歷史範圍，不應取代本節新方向。

## 下一批：綜合實作部分交付（2026-11-05）

> 2026-11-05 後續：本機初版已把「正式綜合實作＋商店實習」實作完成（見下一節「第二批」），本節的示例仍保留為額外練習材料（`/api/java-route/example-starter`），不計分、不解鎖實習。

本批目標：在不預設未確認的正式題目與評分權重下，提供可下載、本機可運行的 Java 綜合實作示例骨架。示例只是準備材料，不計分、不開放提交或進入模擬實習。使用者要求 Java 程式隔離檢查與正式評分；現有 Python 鏡像不能直接證明支援 Java，本機未見 Java 檢查鏡像，故正式環節待題目、權重、評分方法及安全執行環境確定。

範圍：沿用現有 Java 路線、登入與版面，為學生提供標明示例的比賽管理項目及下載入口；項目僅使用標準 Java 並提供中文本機運行與待完成工作的說明。驗收：學生下載後可依說明在本機編譯運行骨架；未登入及非學生角色不得下載；頁面及項目均明確沒有評分、不解鎖實習；現有進度、AI 額度及班級流程不退化。測試使用隔離資料；不操作遠端及真實 AI。

## 第二批：綜合實作與商店實習（2026-11-05 本機初版，待驗收）

**目標**：把學習路線接到可操作的實作流程：綜合實作上傳檢查 → 通過後解鎖商店三項工作；檢查在隔離容器實際執行，AI 只按需解釋。

**本批範圍**

- 綜合實作（比賽報名系統，開發者選定題目）：起始專案、規則文件、學生測試要求、上傳 ZIP、容器檢查、100 分評分（核心 45／學生測試 20／程式結構 20／設計解釋 15）、必要條件與 70 分門檻、每項 3 次有效檢查、環境故障不計次、教師／管理員重設。
- 商店模擬實習：查詢商品、建立訂單、查看訂單三項工作，依序解鎖；附本機可操作前端；同一專案延續提交。
- AI：解釋實際檢查結果、評分設計解釋；主動點擊才呼叫；共用每日 10 次額度。
- 舊實訓入口維持隱藏；原程式、學生資料、教師班級功能保留。

**驗收**

1. 學生登入 → 學習路線 → 工作台可見四個階段與解鎖狀態；未通過綜合實作時商店不可提交。
2. 上傳參考解答 ZIP → 容器實際檢查 → 顯示逐項結果與 85/100 通過、剩餘次數減少；重新登入保留。（2026-11-05 第三批已改為設計解釋評分後才通過，見下節。）
3. 上傳未完成版本 → 核心與測試失敗、不通過；三次後鎖定，教師（本班）或管理員重設後恢復。
4. 通過綜合實作後，依序完成三項商店工作；每項全部檢查通過才解鎖下一項。
5. Docker／鏡像不可用時顯示環境故障、不扣次；AI 不可用時程式檢查仍正常。

**不包含**：Java 執行以外的語言、非同步檢查佇列、多學生容量承諾、教師查看答題名單、資源更新後台。


## 第三批：收尾補齊（2026-11-05 本機完成，待使用者驗收）

**狀態（2026-11-05）**：本機實作與自檢完成，尚未部署、未重啟使用者的 8000 服務、未做真人／真實 AI 驗收。實際結果見下方「本批實際結果」。

**目標**：讓「設計解釋」成為綜合實作真正的必經環節，補上 AI 不可用時的人工評分通道，並修正本機啟動腳本；不新增大功能。

**依據**：使用者 2026-11-05 確認「設計解釋必須評分才算通過」，見[需求總覽](項目需求總覽.md)的規則變更。以下工程做法由本批決定。

**範圍**

1. 後端 `backend/java_course.py`：設計解釋未評分時一律不通過並說明原因；總分按含設計分的 0–100 呈現，未評分時分開顯示「設計解釋 0/15（待評分）」。
2. 教師／管理員人工評分：新增端點，教師限本班學生、管理員不限；輸入 0–15 整數；保存評分者、時間、來源（AI／人工）與歷史。評分後重算該次提交的通過狀態與商店解鎖，不改寫客觀檢查結果，也不追溯撤銷已通過的舊紀錄。
3. 前端：教師工作台 Java 面板顯示設計解釋原文、目前分數與來源及評分表單；學生工作台清楚顯示待評分／已評分與是否通過。
4. 修正 `scripts/start.ps1` 在 Windows PowerShell 5.1 下的編碼問題（見[技術債](技術債與Bug.md)），不改啟動行為。
5. 記錄 `training/java-example/` 與 `/api/java-route/example-starter` 已是無入口示例；保留不刪，待使用者決定用途。

**不包含**：重寫商店或綜合實作題目、資源核實、真實 AI 聯調、部署、非同步檢查佇列。

**驗收**：未評分時檢查不通過且不解鎖商店；教師評分後狀態正確更新；非本班教師不能評分；0 分且總分不足不通過；客觀檢查與舊紀錄不被改寫；後端測試、前端測試與建置通過；開發者以隔離資料與 8001 埠實測，不動使用者的 8000 服務。

**停止點**：完成實作、自檢與文件更新後停止回報，交使用者人工驗收。

**本批實際結果（2026-11-05）**

- `backend/java_course.py`：`grade_practice` 未評分一律不通過並說明原因；新增教師 `POST /api/teacher/java/design` 與管理員 `POST /api/java/design`，0–15 整數、教師限本班、保存評分者／時間／來源／歷史，重評只重算該提交最新一次尚未通過的有效檢查，已通過紀錄不撤銷；教師與管理員進度端點附上最近設計解釋原文與評分狀態。AI 評分改用同一份設計分結構（`source=ai`、`grader=ai`），與人工（`source=manual`）區分。
- 前端：`JavaResetPanel` 顯示學生設計解釋原文、目前分數與來源，提供 0–15 評分／重新評分表單；`JavaCourse` 顯示「客觀＋結構 x/85」與「設計解釋 x/15 或 0/15（待評分）」，未評分時明確說明不能通過、商店不解鎖。
- `scripts/start.ps1` 改存 UTF-8 with BOM，內容與啟動參數不變；Windows PowerShell 5.1 剖析器回傳 0 錯誤。
- 自動檢查：後端 `pytest tests -q` 64 項通過（含 12 項 Java，真實容器案例會先斷言未評分不通過，再由管理員評 15 後通過）；前端 `npm test` 3 項通過、`npm run build` 通過，`frontend/dist` 已更新（`index-ClZ4utjK.js`／`index-BYJqGXnG.css`）。
- 隔離實測（8001、全新 `%TEMP%` 資料、AI 指向 `http://127.0.0.1:9`、無真實付費請求）：上傳 `practice-reference.zip` → 真實容器 85/100、設計待評分不通過、商店未解鎖 → 教師評 15 → 100/100 通過、商店解鎖 → 非本班教師與非成員教師皆 404 → 管理員重評 12，舊 15 分與已通過紀錄保留。
- 未驗證：教師評分表單的實際瀏覽器操作與手機畫面（此安裝的瀏覽器預覽不可用）、真實 AI 設計評分品質與費用、真人驗收；`scripts/start.ps1` 未實際啟動 8000（避免影響使用者現有服務），只做 Windows PowerShell 5.1 語法剖析。

## 首批開發任務與驗收（2026-11-05，已完成本機初版）

**目標**：一名學生登入後能查看 Java 後端路線、打開資源、保存完成標記並按需向 AI 提問；隱藏原實訓入口但保留原資料。這是整體 MVP 的第一批，不代表綜合測試或模擬實習已交付。先由開發者核對現有程式和隔離資料，再依項目規則完成並交由使用者驗收。

**範圍**：九個已確認主題按既定順序顯示，可自由瀏覽與跳過；各資源展示名稱、來源及連結，僅使用通過中文／免費／內地可訪問核實的資料，未通過核實的項目顯示「資源待核實」，不假稱完整。資源以穩定識別碼綁定學生自己的完成狀態，重新登入仍保留；長影片整套或小節標記暫緩，第一批不自行決定。隱藏學生端所有舊實訓入口，包括繼續學習、班級與教程中的入口；不得刪除原程序、資料或已有角色。具體處置須核對既有教師流程，避免誤稱已驗證。

**AI**：在路線中主動提問，不自動調用；每學生每日學習答疑與日後檢查解釋共用 10 次。建議以中國時間零時重置、後端統一計數及顯示餘額；失敗但供應商可能計費的情況需明確呈現並留記錄，具體配額處理待驗證。避免跨用戶資料混入；缺模型或調用失敗時提供清楚狀態。對答疑額度、重試與並發先驗證實際行為，不使用付費請求冒充真人驗收。

**驗收**：①學生登入後只見 Java 入口，舊資料在隔離副本中前後核對未損壞；②九主題可自由進入，已核實資料能打開，未核實項顯示狀態；完成標記可設定／取消，重新登入保留、學生間隔離；③用模擬模型驗證只有主動發問才調用、每日額度共用、到限拒絕、跨日重置、錯誤提示及並發不超額；④確認沒有階段小測或強制順序；首批交付時綜合實作與模擬實習標為尚未開放，第二批已開放，見上方。⑤既有登入及教師必要流程回歸，使用隔離測試資料。真實模型、內地訪問和使用者驗收分開記錄。

**不包含（首批範圍）**：Java 程式執行、綜合實作、商店實習、AI 同事、多學生並發容量承諾及資源更新後台。第二批已擴展綜合實作與商店實習，見上方。AI 金鑰沿用既有部署配置，不暴露密鑰；測試時隔離並避免真實扣費。前端頁面涉及設計，開發前遵循項目 UI Skill 規則。發現新 Bug 依指引記錄。

# 學生帳號註冊 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan in the current chat. User explicitly requested writing the plan followed by implementation; continue without a second approval gate.

**Goal:** 新增學生註冊頁，成功後返回登入頁，由學生自行輸入密碼登入。

**Architecture:** React 獨立註冊元件接入既有登入分支，FastAPI 獨立註冊模組接入 `create_app`。呼叫既有 `Store.create_user`，沿用 SQLite 唯一帳號約束、原子建立初始學習狀態及 scrypt 密碼雜湊，不修改儲存模組。

**Tech Stack:** 現有 React / TypeScript / FastAPI / SQLite；不新增依賴。

**Spec:** 本文件中的流程、接口與限制。

## 流程與接口

登入頁 →「註冊學生帳號」→ 填寫並提交 → 成功返回登入頁 → 帳號已帶入、密碼為空、顯示「註冊成功，請輸入密碼登入」。提供返回登入入口，錯誤留在註冊頁。

`POST /api/auth/register` 接收 `username`、`password`、`confirm_password`；201 回傳 `username` 與成功訊息，不建立 session、不設定登入 cookie。

帳號前後空白移除後為 3–30 位英文字母、數字、底線或連字號，大小寫沿用既有登入及 SQLite 語義。密碼為 10–200 個字元，不能全為空白，前後空白不自動移除；兩次密碼必須一致。409 表示帳號重複，422 表示輸入不符，429 表示同來源一分鐘超過五次註冊嘗試。

## Global Constraints

- 新帳號固定 `role='student'`、`is_demo=False`，不接受客戶端指定權限。
- 不回傳密碼或密碼雜湊，不將密碼寫入浏览器儲存或工作記錄，不調用 AI。
- 使用 `/auth/` 路徑，沿用來源檢查並避開一般學習操作的冪等記錄。
- 註冊請求不自動重試：網絡中斷時說明結果可能不確定，提示嘗試登入。
- 使用既有青綠配色與登入頁布局，新增樣式限定於認證頁。
- 與「写代码 (2)」共用目錄，只局部修改 App.tsx、main.py、main.tsx；不改其補練邏輯或 storage.py。
- 遵循之前的人工驗收偏好：執行構建和語法檢查，不跑自動行為測試，不發起新 AI 調用。

## Review Focus

- 重複帳號與同名並發註冊：資料庫唯一約束避免建立兩個帳號，失敗時顯示明確提示。
- 密碼不一致、過短、過長或空白：前端引導，後端再次檢查。
- 偽造角色：只能建立普通學生帳號。
- 重複點擊或網絡結果不確定：防止重複提交，不自動重試建立帳號。
